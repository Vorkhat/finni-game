## UI

Реализованы Boot/Splash, Welcome, объяснение «Нужно / Хочу / Коплю», выбор реального питомца и его внешности, валидация имени, выбор одной из трёх целей, динамический Home и настройки. Для бюджета, магазина, копилки, заданий и прогресса доступны отдельные страницы с возвратом, без фиктивной финансовой логики.

Home использует профиль: имя, вид, внешность, стадию, кошелёк, накопления, цель, прогресс и PetState. Задание берётся из контента, CTA зависит от текущего периода и подтверждения плана. Настройки сохраняют предпочтения звука/анимаций; системный reduced motion соблюдается. Есть семантические подписи, нативные progress и dialog, видимое выделение выбранных вариантов и safe-area отступы.

## Persistence

Профиль создаётся и обновляется через `GameService → Shared Domain → StorageAdapter → localStorage`. Новый результат публикуется в UI только после успешного сохранения. Ключ профиля — `finni.game-profile`; предпочтения UI хранятся отдельно в `finni.preferences`.

Без профиля Boot открывает обучение; сохранённый профиль открывает Home. Если создание прервалось до выбора цели, восстанавливается выбор цели. Ошибка чтения не стирает сохранение.

Тесты проверяют сохранение питомца и цели, повторную загрузку, равенство сохранённого профиля, реальные балансы 0/0 и 70/30, прогресс цели и текущий подтверждённый период. Есть проверка, что неудачное сохранение не публикует несохранённое состояние.

## E2E

Playwright запускает production preview без backend. На каждом из трёх размеров выполняются три сценария:

1. Чистое хранилище → обучение → кот → внешность → имя Финни → Самокат → Home → reload; переходы по разделам и возврат.
2. Дракон → проверка неверных имён → возобновление выбора цели после reload → Космическое путешествие → Home → настройки и повтор обучения без потери питомца.
3. Сохранённый профиль с балансами 70/30 и подтверждённым периодом → реальные значения Home → reload и reduced motion.

Проверяются загрузка изображений, отсутствие горизонтального переполнения, доступность нижней навигации, отсутствие наложения Welcome-текста на персонажа и перенос длинной цели не более чем на две строки. Первый сценарий перехватывает и отклоняет внешние/API-запросы; их число равно нулю. Поиск в клиентском runtime-коде также не обнаружил fetch, axios, API URL или внешних шрифтов/изображений.

## Remaining risks

- Проверка проведена в Chromium с мобильными viewport, не на физическом Android-устройстве. Системный Android Back и реальные safe-area требуют проверки после упаковки.
- Web-preview работает без игрового backend и внешних ресурсов, но требует локального сервера для раздачи файлов. PWA offline-кеш и Android wrapper ещё не реализованы.
- Звук пока только сохранённое предпочтение: аудиоассетов и звуковых эффектов на этом этапе нет.
- localStorage остаётся устройственным хранилищем: очистка данных браузера удалит профиль, облачного восстановления нет.
- Полные игровые взаимодействия, TaskRenderer, развитие, взрослый раздел и Demo UI не входят в Этап 1. В матрице требований они не отмечены DONE.
